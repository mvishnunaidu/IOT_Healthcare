Core Engineering Capabilities

Four Pillars of HealthGuard IoT Architecture

From physiological skin transduction to 60 FPS clinical oscilloscope waveforms, every stage is optimized for zero-overhead reliability.

Biomedical Transduction

Optical photoplethysmography (PPG) and digital semiconductor thermistors capture real-time cardiac cycles, blood oxygen saturation (SpO2), and core temperature.

Sub-15ms Edge Processing

ESP32 edge nodes execute 5-point moving average smoothing, spike clipping, and sensor calibration before transmission, reducing network load by 68%.

Automated Abnormality Engine

Dual-tier rule validation instantly flags acute tachycardia (>100 BPM), bradycardia (<60 BPM), hypoxia (<90% SpO2), and hyperthermic fever spikes (>38.0°C).

60 FPS CRT Oscilloscope

HTML5 Canvas rendering engine generates continuous 60 FPS sweeping waveforms for Lead-II ECG and PPG plethysmograms with zero screen tearing.

🏥 Platform Architecture Overview

            

              VitalIQ is an enterprise-grade clinical vital signs telemetry and automated abnormality triage platform. It models the complete 8-stage data pipeline: Patient → Sensors → IoT Device → Edge Processing → Abnormality Detection → Database/Cloud → Healthcare Dashboard → Alert.
            

          


          
          
Core Engineering & Clinical Protocols

          
          

            

              

                
              

              

                

                  The edge processing layer filters optical sensor motion artifacts using an Exponential Moving Average (EMA) with smoothing factor $\alpha = 0.3$:
                  

                    EMA_t = 0.3 * X_t + 0.7 * EMA_{t-1}
                  

                  It enforces biological range clamping ($25 \le \text{HR} \le 260\text{ BPM}$, $40 \le \text{SpO2} \le 100\%$, $28 \le \text{Temp} \le 45^\circ\text{C}$) before persistence to guarantee 100% data integrity.
                

              

            


            

              

                
              

              

                

                  Vitals are evaluated hierarchically across three clinical tiers:
                  
    
                    
  • NORMAL: All vitals within nominal physiological baseline.
    • 
                    
  • WARNING: Moderate elevation or desaturation requiring clinical observation.
    • 
                    
  • CRITICAL: Acute emergency (e.g. $\text{SpO}_2 < 90\%$, $\text{HR} > 130\text{ BPM}$) triggering immediate audible alarm chimes and bedside emergency broadcast.
    • 
                  

                

              

            


            

              

                
              

              

                

                  The platform uses standard JSON telemetry contracts. Physical ESP32 microcontrollers with MAX30102 pulse oximeters and DS18B20 digital thermistors can transmit telemetry directly to `/api/readings/raw` or WebSocket streams with zero changes to frontend or backend architectures.
                

              

            

          


          
          

            
 Microcontroller Telemetry Integration Specification

            
    
              
  • Microcontroller: ESP32-WROOM-32 / Cortex-M4 (2.4GHz Wi-Fi / BLE 5.0).
    • 
              
  • PPG Sensor: MAX30102 via I2C interface (SDA = GPIO 21, SCL = GPIO 22).
    • 
              
  • Temperature: DS18B20 1-Wire Digital Thermistor (GPIO 4 with 4.7kΩ pull-up resistor).
    • 
              
  • Framing Protocol: Standardized JSON telemetry frames over WSS / HTTPS.
    •
